# 常见错误排查

---

## 错误码说明

| 错误码 | 名称 | 严重程度 | 说明 |
|--------|------|----------|------|
| E1001 | 认证失败 | P1 | API Key 无效或已过期 |
| E1002 | 权限不足 | P2 | 当前 Key 没有该操作权限 |
| E2001 | 请求超时 | P2 | 服务器响应超过30秒 |
| E3001 | 资源不足 | P2 | 账户配额已用尽 |
| E4001 | 格式错误 | P3 | 请求参数格式不正确 |
| E5001 | 服务维护 | P1 | 系统正在维护中 |

---

## E1001 - 认证失败

### 症状
API 返回 `{"error": "E1001", "message": "Authentication failed"}`

### 可能原因
1. API Key 拼写错误
2. API Key 已过期或被禁用
3. 使用了错误的认证方式

### 解决方案
1. 检查 API Key 是否正确复制（注意大小写）
2. 登录控制台重新生成 API Key
3. 确认请求Header格式为: `Authorization: Bearer YOUR_KEY`

---

## E2001 - 请求超时

### 症状
API 无响应，最终返回超时错误

### 可能原因
1. 网络连接不稳定
2. 请求数据量过大
3. 服务器负载过高

### 解决方案
1. 检查本地网络连接
2. 减少单次请求的数据量
3. 实现请求重试机制（建议3次，间隔2秒）
4. 避开业务高峰期（上午10-11点，下午3-4点）

---

## E3001 - 资源不足

### 症状
返回 `{"error": "E3001", "message": "Quota exceeded"}`

### 可能原因
1. 月度API配额已用完
2. 存储空间已满
3. 并发请求数超限

### 解决方案
1. 登录控制台查看当前使用量
2. 升级到更高套餐
3. 等待下个月配额重置
4. 优化代码减少不必要的API调用
